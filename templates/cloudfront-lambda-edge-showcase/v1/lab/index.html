CloudFront + Lambda@Edge

This page runs live checks against the CloudFront distribution that serves it. Each card exercises one part of the stack — an edge function trigger, the dynamic API, or the signed-URL protection — and explains what it does and what a correct result looks like. Because this page is served by the same distribution, the checks run same-origin, so no CORS gets in the way.

Edge authentication

viewer-request idle

What it is: a Lambda@Edge function that runs on the viewer request — the first hook, before CloudFront checks its cache. The classic place for an authentication gate.

What this checks: the protected root / requires HTTP Basic auth. Without credentials the edge should answer 401 before reaching the origin. With demo:demo it should let you in.

URL rewrite (SPA routing)

      origin-request
      idle
    

    

      
What it is: a function on the origin request
      hook — it runs only on a cache miss, right before CloudFront goes to S3. Cheap,
      because its result can be cached.

      
What this checks: a directory path like
      /lab/anything/ is rewritten to
      /index.html so a single-page app resolves. A
      200 means the rewrite worked.

Security headers

      origin-response
      idle
    

    

      
What it is: a function on the origin response
      hook — runs after the origin answers, before caching, so it adds headers once and
      serves them from cache afterwards.

      
What this checks: the response should carry
      Strict-Transport-Security,
      Content-Security-Policy and more. Browsers hide some
      headers from JavaScript even when present — also confirm in DevTools → Network.

A/B testing cookie

      viewer-response
      idle
    

    

      
What it is: a function on the viewer response
      hook — the last step before the answer reaches the browser. Good for per-visitor
      personalization.

      
What this checks: the edge assigns you to group A or B
      and pins it with an abtest cookie. If set
      HttpOnly, JavaScript cannot read it — check DevTools →
      Application → Cookies.

Dynamic API

      API Gateway v2 → Lambda
      idle
    

    

      
What it is: a regular (non-edge) Lambda, the
      counterpoint to the edge functions. CloudFront routes
      /api/* to an HTTP API (API Gateway v2), which invokes
      the function.

      
What this checks: calling
      /api/hello should return 200 with a JSON
      greeting from the Lambda.

Signed-URL protection

      trusted key group
      idle
    

    

      
What it is: the /premium/*
      path is locked behind a CloudFront trusted key group. Only requests carrying
      a valid signature (a signed URL) get through.

      
What this checks: opening
      /premium/secret.html without a signature should
      be refused with 403 MissingKey. That refusal is the feature working — the
      content is not publicly reachable.

    

    

      
    

    

  







  
About this lab. It is the test page shipped with the
  cloudfront-lambda-edge-showcase template. The
  demo:demo credentials are illustrative only — in
  production you would validate a signed token instead.

  

    
4 edge triggers
viewer-request, origin-request, origin-response and viewer-response — one function each.

    
Edge runs in us-east-1
Lambda@Edge is created in us-east-1 and replicated globally by CloudFront.

    
Edge vs. regular
The API Lambda contrasts with the edge ones: it takes env vars and a longer timeout.

    
Propagation
After an apply, edge functions take a few minutes to reach every location.
