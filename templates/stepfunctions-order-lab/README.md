# stepfunctions-order-lab — assets

Source code shipped with the `stepfunctions-order-lab` template.

| Template version | Asset version |
|---|---|
| v1 | `v1/` |

## v1

Seven Lambda handlers, all runtime `nodejs22.x`, handler `index.handler`. The
apply zips each folder as it is. Every dependency (`@aws-sdk/client-dynamodb`,
`@aws-sdk/client-sfn`, `@aws-sdk/client-sqs`) is bundled in the managed
runtime; nothing is installed at deploy time.

The workflow itself is not in this folder: its definition is the `definition`
field of the state machine in the diagram, where it references the functions,
the table, the queue and the topic by their Terraform addresses.

### The workflow

The execution name is the order id, so every step and every record of an order
uses the same value.

| State | Type | What it shows |
|---|---|---|
| `ValidateOrder` | Task (Lambda) | `Catch`: an `InvalidOrder` error goes to `MarkRejected` |
| `SaveOrder` | Task (DynamoDB `PutItem`) | a direct service integration, with no Lambda |
| `NeedsApproval` | Choice | a total above 1000 waits for a person |
| `WaitForApproval` | Task (SQS, `.waitForTaskToken`) | callback: the execution waits for `SendTaskSuccess` or `SendTaskFailure`, 5 minutes at most |
| `ReserveStock` | Task (Lambda) | a business error, `OutOfStock`, from a conditional write |
| `ChargePayment` | Task (Lambda) | `Retry` with backoff for `PaymentGatewayUnavailable`; a declined card is not retried |
| `ReleaseStock` | Task (Lambda) | compensation: the stock goes back before the order fails |
| `PackItems` | Map | one `PackItem` per line, at most 3 at the same time |
| `CompleteOrder` | Parallel | `MarkCompleted` (DynamoDB `UpdateItem`) and `PublishCompleted` (SNS `Publish`) at the same time |
| `MarkRejected`, `MarkApprovalTimedOut`, `MarkPaymentFailed` | Pass | each sets the outcome, and `RecordOutcome` writes it |
| `OrderFailed` | Fail | error and cause taken from the outcome |

### The table

One DynamoDB table, `pk`/`sk`, holds everything:

| `pk` | `sk` | Written by |
|---|---|---|
| `PRODUCT` | the SKU | `order-console` (first page load and **Restock**), `order-reserve`, `order-release` |
| `ORDER` | the order id | the workflow, `order-reserve`, `order-approval-inbox`, `order-console` (approval) |
| `EVENT` | `<time>#<message id>` | `order-console`, from the notifications queue |

The order id starts with the time in base 36, so a `Query` on `ORDER` in
descending order lists the newest orders first. No function scans the table.

### The functions

- `v1/lambda/order-console/` — the page (`page.html`) and its API, behind a
  Lambda Function URL. It starts executions with one of seven scenarios or an
  order built on the page, follows an execution step by step from its history,
  approves or rejects an order waiting for approval, and lists the
  notifications. The products are written the first time the page loads, when
  the table has none.
  Reads at runtime:
  - `AWS_DYNAMODB_TABLE_NAME_*` — the table.
  - `AWS_SFN_STATE_MACHINE_ARN_*` — the state machine it starts and reads.
  - `AWS_SQS_QUEUE_NAME_*` — the notifications queue. The queue URL is built
    from the region, the function's account and this name.
- `v1/lambda/order-validate/` — `ValidateOrder`. Checks the customer, 1 to 10
  lines, one line per SKU, quantities from 1 to 20, prices above 0 and a 4-digit
  card, and returns the order with its total. Reads no variable.
- `v1/lambda/order-reserve/` — `ReserveStock`. Takes every line out of stock in
  one DynamoDB transaction, with a condition per line; `OutOfStock` names the
  SKUs short of stock. Reads `AWS_DYNAMODB_TABLE_NAME_*`.
- `v1/lambda/order-charge/` — `ChargePayment`. A simulated gateway: nothing is
  charged. The scenario `flaky` fails the first two tries
  (`PaymentGatewayUnavailable`), and the card `0000` is declined
  (`PaymentDeclined`). Reads no variable.
- `v1/lambda/order-release/` — `ReleaseStock`. Puts back what `ReserveStock`
  took. Reads `AWS_DYNAMODB_TABLE_NAME_*`.
- `v1/lambda/order-pack-item/` — `PackItem`, once per line. Waits 1.5 to 3
  seconds, so the overlapping times show the Map running lines in parallel.
  Reads no variable.
- `v1/lambda/order-approval-inbox/` — triggered by the approvals queue. Stores
  the task token on the order and marks it `AWAITING_APPROVAL`, which is what
  makes the page show **Approve** and **Reject**. Reads
  `AWS_DYNAMODB_TABLE_NAME_*`.

Each variable is generated by the diagram from the function's connection: the
type at the other end, the value, and the connection's label (`0` without one).
The functions use the first variable of each prefix, in name order, so renaming
a node or copying the template changes nothing in the code. The same
connections grant the permissions.

### Notifications

The SNS topic delivers to the notifications queue, and the page reads that
queue. Three things publish to the topic:

- the workflow, when an order completes (`PublishCompleted`);
- an EventBridge rule, when an execution ends `FAILED`, `TIMED_OUT` or `ABORTED`;
- a CloudWatch alarm on the state machine's `ExecutionsFailed`.
